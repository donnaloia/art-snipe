# Pipeline Breakdown

## Goal

Take one gameplay mockup and produce engine-ready 2D asset files with no manual bounding-box entry, no manual prompt writing, and no manual segmentation work.

## Final Pattern

```text
mockup
→ vision analysis (Gemini)         → produces full manifest with bboxes
→ segmentation (local SAM + rembg) → produces clean reference cutouts
→ image generation (OpenAI)         → produces 3 candidates per asset
→ human approval (review UI)        → approves chosen candidate
→ variant generation                → PIL transforms or image gen per variant
→ validation                        → checks size + RGBA per variant
→ export                            → copies to game_assets/
```

## What Is Automated

- **Asset discovery** (what's in the mockup) — vision model
- **Localization** (where each asset is) — vision model returns bboxes
- **Prompt generation** (what to ask for) — vision model writes per-asset prompts
- **Segmentation** (clean cutouts) — local SAM
- **Image generation** — OpenAI gpt-image-1
- **Variant generation for UI states** — deterministic PIL transforms for hover, pressed, disabled, selected, damaged
- **Variant generation for everything else** — image gen with variant-aware prompt suffix
- **Validation** — automated dimension + mode check
- **Export** — automated copy

## What Stays Human

Taste decisions in the **review UI**: which of the 3 candidates per asset best matches your project's vision. This is the only required manual step.

## Why the Manifest Matters

The manifest is the source of truth for the rest of the pipeline. It determines:

- which assets get generated (by ID)
- target output dimensions (per asset)
- bbox to use for segmentation (per asset)
- which variants to produce (per asset)
- whether text should be baked into the image (per asset)
- destination category folder under `game_assets/`

The manifest is auto-generated by `artpipe analyze` from the vision model's output. You can hand-edit it between steps if you want to tweak prompts, sizes, or variant lists before running `generate`.

## Important Rule

Reference cutouts (output of `segment`) are not final art. They're hints for the image generator. The generator redraws each asset entirely; the reference's job is to communicate proportions, composition, and rough silhouette.
